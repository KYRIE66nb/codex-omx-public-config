# 工作流

本文件用于统计型建模赛题的端到端编程：目标不是“跑一次代码”，而是产出可解释、可复现、可写进论文的模型结果。

## 阶段 0：检查数据与输出契约

先弄清楚：

- 原始数据文件、上游生成文件、下游需要生成的文件；
- 个体键、时间键、分组键、场景键；
- 空白、`N/A`、`0`、负数、特殊字符串等值的语义；
- 题目要求的输出：估计值、确定性、不确定性、比较结果、案例分析、建议、因素影响；
- 论文或 PPT 需要哪些图。

编码前写清楚输入输出契约：

- 输入路径；
- 输出目录；
- 输出 CSV 名称；
- 主键列；
- 单位和归一化方式；
- 随机种子、抽样次数、迭代次数。

## 阶段 1：数据层

数据层脚本应该：

- 保留原始列；
- 安全地把可转数值的字符串转成数值；
- 建立 `observed_mask`、`eligible_mask`、`denominator_mask`、`sentinel_zero_mask` 等掩码；
- 原始数据是宽表而模型需要面板表时，同时导出宽表和长表；
- 对归一化结果做分组/时间内求和检查；
- 导出一份简短的数据质量摘要。

推荐输出：

- `processed_wide.csv`;
- `processed_long.csv`;
- `time_summary.csv`;
- `data_quality_report.txt`.

## 阶段 2：基线模型

先实现最容易解释的基线：

- 均值、排名、归一化份额、相关系数、回归或确定性打分；
- 每个转换一个清晰函数；
- 输出足够的中间结果，用来判断方向是否合理。

不要因为后来用了复杂模型就删掉基线。基线对调试、论文解释和机制比较都很有用。

## 阶段 3：统计模型

按题目需要加入模型层：

- 已知结果能写成不等式时，使用约束过滤或可行域搜索；
- 可行域复杂时，用蒙特卡罗抽样或拒绝采样；
- 估计对象隐藏或噪声大时，用贝叶斯、bootstrap 或重复仿真给出不确定性；
- 比较规则、政策或机制时，用反事实回放；
- 题目问“哪些因素重要”时，做特征效应建模。

模型输出要和处理后数据分开。推荐命名：

- `bounds.csv`;
- `estimates.csv`;
- `simulation_detailed.csv`;
- `simulation_summary_diff.csv`;
- `case_studies.csv`;
- `effect_summary.csv`.

## 阶段 4：验证与稳健性

美化图表前先验证：

- 已知决策或标签的点估计复现率；
- 后验样本或 bootstrap 样本复现已知结果的概率；
- 安全边际、松弛量或决策边际分布；
- 标准差、置信区间宽度或可信区间宽度；
- 份额或概率估计的熵、集中度指标；
- 对随机种子、权重、阈值、先验、抽样次数的敏感性；
- 对边界样本、异常样本和高影响样本做案例审计。

如果指标很差，先检查指标定义和真实决策规则是否对齐，再调参数。

## 阶段 5：结果与图表

单独写可视化或报告脚本。它应该：

- 只读取前面阶段保存的输出；
- 同时生成 PNG 预览图和 SVG/PDF 矢量图；
- 生成一份文本或 Markdown 报告，列出论文会用到的关键数值；
- 不依赖 notebook 里的隐藏状态，除非用户明确要求用 notebook。

每张最终图都要有：

- 一句话说明它支持什么结论；
- 可解释的坐标轴标题和单位；
- 清晰图例；
- 与数据尺度一致的视觉编码；
- 需要放进论文或 PPT 时，提供可编辑文字的矢量版本。

## 术语抽象规则

把领域词先映射成统计角色：

- 专家评分、传感器读数、问卷响应、人工标注 -> 观测信号；
- 隐藏需求、隐含偏好、未知概率、保密计数 -> 隐变量目标；
- 周次、轮次、时期、批次 -> 时间索引；
- 赛季、地区、方案、实验组 -> 分组索引；
- 终止事件、失败、被选择、已知标签 -> 已知决策/结果；
- 候选集合、有效记录、可比较对象 -> 分母集合。

只有在当前数据真的使用这些词时，才在代码列名和图表标题里使用这些领域词。
