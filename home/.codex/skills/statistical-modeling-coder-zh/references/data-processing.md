# 数据处理

本文件用于清洗统计型赛题数据，尤其适合带有重复时间、来源、评分者、传感器、场景或重复实验列的宽表。

## 缺失值语义

不要把所有“看起来缺失”的值统一处理。

- `N/A` 可能代表结构性不存在，比如某个来源、评分者、设备或重复实验本来就不存在。确认语义后，通常应转成 `NaN` 并在求均值时排除。
- `0` 可能是真实零值，也可能是“不适用/不在范围内”的哨兵值。必须结合题面、邻近列和结果列判断。
- 空白可能代表未观测，也可能代表不适用。需要记录你的解释。

当某个值代表“不该进入分母集合”时，建立掩码，不要直接填补：

- `observed_mask`：该观测存在，能参与聚合；
- `eligible_mask`：该个体属于当前时间/场景下的比较对象；
- `denominator_mask`：该行能进入份额、排名、均值等计算的分母；
- `sentinel_zero_mask`：零是结构性编码，不是真实数值；
- `final_status` 或 `outcome_rank`：最终结果标签或排名。

使用 `np.nanmean`、过滤后的 `groupby` 等方式，避免结构性缺失拉低统计量。

## 宽表转长表

对 `time1_score`、`week1_score`、`round2_sensor3_value` 这类重复列：

1. 从列名中解析 `time`、`measure` 和可选的 `source`。
2. 转成长表：一行对应一个个体/时间/来源，或一个个体/时间。
3. 先保留来源层级的行，再做聚合，并记录有效来源数量和缺失来源数量。
4. 宽表只作为方便查看的输出；建模和绘图优先使用长表或面板表。

推荐面板列：

- `entity_id` 或稳定名称；
- `group_id` 或场景/分组；
- `time`;
- 原始测量列；
- 归一化测量列；
- 排名列；
- 观测掩码和分母掩码；
- 模型估计列；
- 不确定性列。

## 归一化与排名

在组内或时间内比较时，只在分母集合内归一化：

- 份额：`value_i / sum(value_denominator)`;
- 排名：只对符合资格的对象排名；
- 组成数据份额：做 epsilon 平滑后使用 CLR 等对数比变换；
- z-score：只有当解释是“组内相对位置”时才做。

必须检查：

- 每个组/时间内份额是否加和为 1；
- 排名是否覆盖了正确的分母集合；
- 结构性不适用的行是否被排除在分母外；
- 排名方向是否写清楚，例如 `1` 是最好，还是数值越大越好。

## 结果列

使用稳定、明确的列名：

- `mean_estimate`, `sd_estimate`, `ci_lower`, `ci_upper`;
- `min_feasible`, `max_feasible`;
- `posterior_prob_consistent`;
- `decision_margin`;
- `entropy`;
- `rule_name`;
- `score_method_a`, `score_method_b`;
- `predicted_outcome`, `actual_outcome`, `is_consistent`.

如果有最终名次或终止结果：

- 持续时间写成 `duration_periods`;
- `1st`, `2nd`, `3rd` 这类文本只放在展示用名次列；
- 不要把 `winner`、数字、中文说明混在同一个分析列里。

## 质量检查

模型读取处理后数据前，保存或打印：

- 每个组/时间的行数；
- 每个时间的分母集合大小；
- 每个测量列的缺失数；
- 归一化加和检查；
- 早期、中期、后期的边界样本；
- 面板主键是否重复。
