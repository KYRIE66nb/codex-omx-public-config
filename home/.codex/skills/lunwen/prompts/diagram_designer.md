# Diagram Designer Prompt

用于规划论文中的概念图、示意图、框架图、流程图，以及系统型论文里的用例图、功能结构图和概念 E-R 图。

适用场景：

- 科研型论文中的概念图、方法框架图、机制示意图
- 系统型论文中的系统架构图、角色用例图、系统功能结构图、功能流程图、概念 E-R 图
- 需要把抽象文字转成更清晰图示时

默认要求：

1. 图必须服务正文，不是为了凑图
2. 图的结构要与正文描述一致
3. 图的层级不能超过正文能解释的复杂度
4. 图题和正文引用要配套
5. 系统型论文优先复用样文中的图题命名习惯和章节位置
6. 如果用户明确要“ER图”，默认理解为概念 E-R 图，优先 Chen 记法，不要直接给全方框表关系图
7. 默认按“论文优先”处理：先考虑本地 `PNG/.drawio` 主产物，再决定是否进入实时会话精修

论文优先路由判定：

1. 先写清这张图属于哪一章、服务哪段正文、最终要落成什么本地产物（`PNG/SVG/.drawio`）
2. 先选一个主路由，不默认同时调用 `drawio` 与 `next_drawio_live`
3. 只有当基础路由无法满足布局、图标、复杂正交连线、可编辑源文件要求时，才升级到 `next_drawio_live`
4. 如果是论文 / 样文 / 模板上下文，默认由 `lunwen` 统筹，而不是把图示任务独立成通用作图任务

优先输出：

- 图示清单，至少写明图题、放置章节、图示类型、推荐绘图引擎
- 图的用途
- 放置章节
- 图中节点/模块清单
- 节点关系
- 推荐图类型
- 主产物（本地 `PNG/SVG/.drawio` 或结构化源码）
- 主路由、升级条件、回退路由
- 是否需要进入 `next_drawio_live`（是/否 + 原因）
- 必要的图前引导句和图后承接句

推荐图类型：

- 概念关系：概念图
- 方法流程：流程图
- 模型结构：框架图
- 系统模块：架构图
- 数据流：数据流图
- 角色需求：UML 用例图
- 系统拆解：层次化功能结构图
- 数据库概念设计：Chen 记法 E-R 图

系统型论文默认还要输出以下专用判断：

1. 用例图：
   - 参与者是谁
   - 是按角色拆多张图还是合并一张图
   - 是否需要 `include` / `extend`
2. 功能结构图：
   - 顶层系统名是什么
   - 第二层按角色还是按模块拆
   - 每个分支要展开到第几层
3. 概念 E-R 图：
   - 实体清单
   - 关系矩阵
   - 关键属性清单
   - 哪些属性是主键
   - 是否需要先画关键实体属性图再画总体 E-R 图

图示符号的默认规则：

- 用例图：参与者在系统边界外，用例为椭圆，系统边界为矩形
- 功能结构图：采用矩形或圆角矩形层次排布，不混入流程判定菱形和实体属性椭圆
- 概念 E-R 图：实体为矩形，属性为椭圆，关系为菱形；弱实体为双矩形，识别关系为双菱形

引擎选择优先级：

- 概念 E-R 图：`Graphviz DOT`、draw.io、Visio、`canvasdesign`
- 用例图：Graphviz、PlantUML、draw.io、Visio
- 功能结构图：draw.io、`Graphviz DOT`、Visio
- 系统架构图：Graphviz、draw.io、Visio、`canvasdesign`
- 关键流程图：draw.io、Mermaid、PlantUML
- Mermaid `erDiagram`：只用于逻辑表关系草稿，不作为正文概念 E-R 图首选

双 MCP 模型（先主路由，后升级）：

- `drawio`：基础打开器，适合 Mermaid / XML / CSV 的直接打开与轻量处理
- `next_drawio_live`：实时会话增强器，适合增量编辑、XML 自动修复、导出 `.drawio`
- 论文优先：在线会话只是中间工作台，最终交付仍应回到本地 `PNG/SVG/.drawio`
- 默认不要一上来就进入 live 会话；先判断是否必须为了排版、图标、复杂连接而进入 `next_drawio_live`
- 如果 `drawio` / Graphviz / Mermaid / 本地脚本已经足够，就停在基础路由，不再额外切 live

如果需要直接生成可插入论文的本地 `PNG`，默认增加以下路由：

1. 关键流程图、系统功能结构图、逻辑表关系图：
   - 优先输出 Mermaid 定义
   - 再交给 `tools/generate_drawio_assets.py` 走 draw.io lightbox PNG 桥接
2. 用例图、系统架构图：
   - 默认优先输出 Graphviz / 结构化描述，先落本地图片
   - 只有在布局复杂、需要实时微调或需要可编辑 `.drawio` 时，才切到 `next_drawio_live`
3. 概念 E-R 图：
   - 默认输出 `Graphviz DOT`
   - 再走 `tools/render_graphviz.py` 或 `tools/generate_drawio_assets.py` 的 Graphviz 路由产出 PNG
4. 用户明确要求 draw.io 可编辑链接时：
   - 才把 draw.io 链接作为主产物
   - 否则默认主产物必须是本地图片或 `.drawio` 文件

如果环境中存在 `canvasdesign` 或等效绘图能力，优先调用它生成科研型概念图、示意图和框架图；如果没有，再退回 Mermaid / PlantUML / Graphviz / 结构化文字描述。
